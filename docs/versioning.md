# 版本策略

平台使用一套版本号，每个插件使用自己的一套版本号。两边都遵循[语义化版本](https://semver.org/lang/zh-CN/) `MAJOR.MINOR.PATCH`。写入索引的 `version` 不带 `v` 前缀，例如 `0.1.0`。标签名在版本号前加 `v`。

尚未发布任何平台版本或插件版本。

## 版本号与用户数据

任何版本的更新都不得覆盖或删除用户数据。若必须搬迁，只能在用户明确操作下复制到新位置，并保留原数据。

| 级别 | 何时增加 | 安装方式 |
| --- | --- | --- |
| PATCH | 缺陷修复，不改变使用方式 | 平台保持原地可用 |
| MINOR | 向后兼容的新增能力 | 平台保持原地可用 |
| MAJOR | 不再承诺原地继续使用 | 可以要求重新下载平台 |

次版本与补丁版本都必须让当前主版本的平台原地继续可用。主版本可以要求用户重新下载平台，但仍然不得覆盖或删除已有用户数据。

插件的主版本表示该插件自身不兼容的变更。它是否能装上当前平台，由索引字段 `platformCompatibility` 决定，不由插件与平台共用同一个版本号来表示。

## 标签

标签打在已经合并到 `main` 的提交上。

| 对象 | 标签 |
| --- | --- |
| 平台 | `platform-vX.Y.Z`，例如 `platform-v0.1.0` |
| 插件 | `plugin-<id>-vX.Y.Z`，例如 `plugin-hello-v0.1.0` |

`<id>` 与索引中的 `id` 相同。版本是标签末尾 `-v` 之后的 SemVer。索引里的 `version`、标签和发行包必须是同一个版本。插件 ID 本身不要以 `-v` 加版本号结尾，避免和标签后缀混在一起。
