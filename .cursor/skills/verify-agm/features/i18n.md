# Hakimi i18n localization

Hakimi i18n translates the client UI to Chinese at runtime (default `i18n.enabled=true`, `language=zh-CN`). The user changes it from a config center that lives inside the Plugin Center as the hakimi-i18n detail panel, applies changes with `保存并生效`, and can hot-reload plugins.

## Sub-features

- `i18n-default-zh` shows translated UI text on a default launch.
- `i18n-open-hotkey` opens the config center with Ctrl+Shift+L.
- `i18n-open-card` opens it from the Plugin Center card for hakimi-i18n.
- `i18n-disable-save` turns localization off with the `cfg-enabled` switch and `保存并生效`.
- `i18n-cancel` discards an unsaved change with the cancel button.
- `i18n-hot-reload` re-injects plugins with Ctrl+R or `热重载全部`.
- `i18n-dictionary-tools` adds overrides, exclusions and glossary entries, imports/exports JSON, clears the untranslated list.

## How to get to it (user POV)

- Press Ctrl+Shift+L.
- Open the Plugin Center and choose the `Hakimi i18n Deep Localization Engine` card.
- Press Ctrl+R, or choose `热重载全部` in the Plugin Center, to hot-reload.

## Driving it with agm-lab + agm-cdp

Preconditions:

- `$L -Action doctor -RunId <id>` reports `VERDICT: HEALTHY`.
- `<RunDir>\app\plugins\config.json` has `i18n.enabled=true` (the default after setup).

- **Default translation.** Read the sidebar. Run `$C text --run <id> --selector '[data-testid=sidebar-navigation-items]' --out i18n/01_sidebar.txt`. It reads `新建会话`, `自动化`, `自定义配置`, `插件中心` (observed 2026-11-20 by `doctor`). The newest `proof\electron-*.log` contains `[Hakimi i18n] config.enabled=true language=zh-CN` and `[Hakimi i18n] Plugin initialized successfully!`.
- **Hotkey entry.** Press Ctrl+Shift+L. Run `$C key --run <id> --key L --mods ctrl,shift` and `$C wait --run <id> --selector '#cfg-enabled + label, label[for=cfg-enabled]'`. The hakimi-i18n panel shows the enable switch and `#btn-quick-save` (`保存并生效`).
- **Card entry.** Close it (Escape until `data-agm-hub` is `null`), open the hub and choose the card. Run `$C click --run <id> --selector '#agm-nav-hub'` and `$C click --run <id> --selector '[data-testid=plugin-card-hakimi-i18n]'`. The same panel appears.
- **Disable and save.** Flip the switch and apply. Run `$C click --run <id> --selector 'label[for=cfg-enabled]'` and `$C click --run <id> --selector '#btn-quick-save'`. The log gains `Tearing down Hakimi i18n instance... config.enabled=` and `[Hakimi i18n] config.enabled=false`, `config.json` has `i18n.enabled=false`, and the sidebar text returns to English (`New ...`).
- **Proof.** Run `$C text --run <id> --selector '[data-testid=sidebar-navigation-items]' --out i18n/02_sidebar_disabled.txt`, `$C shot --run <id> --out i18n/02_disabled.png` and `Copy-Item C:\AGM_TestLab\VERIFY_<id>\app\plugins\config.json C:\AGM_TestLab\VERIFY_<id>\proof\i18n\02_config.json`.
- **Persistence.** Restart with `$L -Action stop -RunId <id>` then `$L -Action launch -RunId <id>`. The log shows `config.enabled=false` and `skipping domAdapter.start()`, and the sidebar stays English.
- **Re-enable.** Repeat the switch and `保存并生效` to restore `i18n.enabled=true`, so later recipes start from the default.

## Gotchas

- Everything in this file is UNKNOWN until a run records proof, except the default Chinese sidebar, which `doctor` observed once. The selectors come from `plugins/builtin/hakimi-i18n/hakimi-i18n/ui/config-center.js`; confirm them on first run and fix this file if they differ.
- The floating `中/EN` pill `#hakimi-i18n-trigger` is not created when the Plugin Center hub is present (observed absent). Do not wait for it.
- `document.documentElement.lang` stays `en` while the UI is Chinese. Assert on visible text.
- `#cfg-enabled` is a hidden checkbox styled by its `label`; click the label, not the input.
- Earlier lab runs proved disable + F5 by editing `config.json` by hand. That is not the user path and does not count for `i18n-disable-save`.
- Hot reload re-injects all plugins and closes the hub; reopen it before the next step.
